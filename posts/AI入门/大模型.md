# 大模型

## 基础概念：什么是大模型？

大模型（LLM），通常指参数量巨大、基于海量数据训练出来得神经网络模型。目前最主流的大模型大部分都基于Transformer。

---


## 你需要知道的核心术语

 1. **LLM（大模型）**：全称为Large Language Model，基于互联网海量文本训练出来的深度学习模型。

    LLM的本质是不断地预测下一个最可能出现的词。

 2. **Transformer**：现在LLM几乎全部基于该框架。抛弃了传统的顺序计算，使用“注意力机制”，能同时关注数据中所有部分的关系，并大规模并行计算，能够更好地理解上下文。

 3. **Token（词元）**：模型按照Token处理文本信息，一个Token可能是一个汉字、一个英语单词，也可能是单词的一部分。

 4. **上下文窗口（Context Window）**：指模型一次能看到和处理的最大Token数量。对话中的用户提问、模型回答的Token加在一起，才能算是上下文窗口。

 5. **参数量（Parameters）**：指模型内部可以学习的权重数量，通常以B（十亿）为单位。“B格”越大，模型的能力越强。

 6. **Prompt（提示词）**：用户输入的指令或问题，提示词的质量决定了模型输出答案的质量。

 7. **System Prompt（系统提示词）**：预先设定给模型的指令，用于定义模型的角色、行为规范等。（还有角色扮演orz）

 8. **温度（Temperature）**：当模型计算出下一个词可能是 A (70%)、B (20%)、C (10%) 时，**温度**就是用来调整这些概率分布的数学参数。一般取值范围是0-2。

    - **低温（如 0.1 ~ 0.9）**：模型非常保守，只挑概率最高的词（A）。输出的结果高度确定、严谨、可复现。适合写代码、做数学题等。

    - **高温（如 1 ~ 1.8）**：模型变得“发散”，原本概率较低的词（B、C）也有很大机会被选中。输出的结果更加随机、有创意、丰富多样。适合写小说等。

 9. **上下文学习（In-Context Learning, ICL）**：指无需修改模型参数，只要在提示词中给它提供几个例子或相关背景，它就能立刻学会并完成新任务。

10. **思维链（Chain of Thought, CoT）**：CoT 是一种提示词技巧，通过强制模型在输出最终答案前，先展示出**中间的推理步骤**，从而引导模型走向正确结论。相当于你在对话框输入“请展示思考步骤”。

11. **幻觉（Hallucination）**：即胡说八道。模型遇到了训练集或数据库里没有的问题，就会胡编瞎造。可以通过联网搜索缓解这个问题。

12. **Agent（智能体）**：能够独立干活的大模型，可以调用外部API进行工作，比如帮你写个文档，会直接生成docx文档，而不需要你自己动手。LLM是它的大脑。

13. **多模态（Multimodal）**：通俗易懂地来讲，就是给AI装上了五感，让它能看、听、说、读。

    - 单模态：只能处理文字。

    - 跨模态：输入一种格式的数据，输出另一种格式的数据。（文字生图）

    - 多模态：同时输入多种，综合理解输出。

14. **MCP（Model Context Protocol）**：由Anthropic提出的一种**开源标准协议**，只要外部软件或数据源按照MCP开发，LLM就可以直接连接。降低了AI调用工具的门槛。

15. **蒸馏（Distillation）**：让能力强但是体积大的“老师模型”，训练出小巧的“学生模型”，在保留核心能力的同时大幅缩小体积。蒸馏后的模型体积更小、推力更快、部署成本更低。

16. 流式输出：AI 生成一个 token 就发送一个token，用户体验更好。技术上，流式输出使用 SSE（Server-Sent Events）协议，服务端持续推送数据。

## 技术实现链路

1. **训练阶段**
   这是大模型诞生的地方，也是最烧钱、最耗算力的阶段。

   - 预训练（Pre-training）：让AI阅读全网海量文本，将世界知识压缩进几百亿个参数里。

   - SFT（监督微调）：用人类写好的一问一答对，教模型“别人问你问题，你要怎么回答”，可以理解为答题模板。

   - RLHF（基于人类反馈的强化学习）：让人类给模型的多个回答打分，模型根据得分调整策略。

   - 对齐（Alignment）：让模型的行为、价值观符合人类的意图和预期，SFT和RLHF本质上属于对齐。

   - 产出：得到一个通用 LLM 模型。它很强大，但又大又笨重，直接部署成本极高。

2. **模型优化**
   通用模型太大了，没法直接塞进手机或普通服务器。需要做优化，让它“轻量化”且“专业化”。

   - 微调（Fine-tuning）：用特定领域的数据对模型进行训练，让它变成行业专家。

   - 量化（Quantization）：把模型的精度降低（例如从 32 位浮点数压缩到 4 位），大幅减少显存占用，提升运行速度。

   - 蒸馏（Distillation）：让能力强但是体积大的“老师模型”，训练出小巧的“学生模型”，在保留核心能力的同时大幅缩小体积。蒸馏后的模型体积更小、推力更快、部署成本更低。

   - 产出：一个能落地、跑得快、成本低的模型。

3. **开发者驱动**
   模型能力再强，也得靠人通过“提示词”来激活。这一层不需要改代码，全靠技巧。

   - Prompt（提示词）：你输入的指令。提示词写得越清晰，输出越好。

   - System Prompt（系统提示词）：给模型设定一个固定人设（比如“你是一个严谨的代码审查员”）。

   - CoT（思维链）：引导模型“一步一步思考”（诸如“请先分析原因，再给出结论”），能极大提升复杂推理的准确率。

   - 产出：在不修改模型的前提下，把它的潜力榨干。

4. **外部知识**
   模型的知识停留在训练那一刻，且容易胡编乱造。这一层是给模型外接一个“活字典”。

   - Embedding（词嵌入）：把外部的文档变成数学向量。

   - 向量数据库：把向量存起来，方便快速搜索。

   - RAG（检索增强生成）：当用户提问时，系统先去向量数据库搜出相关文档段落，再让模型结合这些段落来回答。

   - 产出：模型拥有了实时、私有的知识库，回答准确率大幅提升，减少胡编乱造。

5. **自主执行**
   这是目前最前沿的方向。模型不再只是一个“聊天框”，而是一个能“干活”的系统。

   - Function Calling（函数调用）：让模型学会输出特定格式的代码，从而触发外部程序（例如让它调用天气 API 查天气）。

   - MCP（模型上下文协议）：标准化 AI 与外部工具、数据源连接的接口（类似 AI 界的“USB 接口”）。

   - Agent（智能体）：大模型 + 记忆 + 规划 + 工具。你给它一个目标，它自己拆解任务、调用工具、循环执行，直到完成。

   - 产出：大模型从“聊天机器人”进化成了能替代人类完成复杂工作的“数字员工”。
