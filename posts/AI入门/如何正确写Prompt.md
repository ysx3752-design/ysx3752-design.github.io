# 如何正确写Prompt？

正确编写 Prompt（提示词）的核心原则是：把大模型当成一个“极其聪明但没有任何背景常识的新员工”。你不能只给它一个模糊的目标，而是要给出清晰的背景、具体的任务、明确的限制和输出格式。

为了减少抽象概念，我们直接使用一套结构化的公式和正反面对比案例来讲解如何正确编写。

---


## 一、 基础模板（CRISPE 框架）

一个高质量的 Prompt 通常包含以下 5 个要素，建议按照这个结构来写：

1. **C - Context（背景）**：提供任务的上下文环境。
2. **R - Role（角色）**：设定模型的身份。
3. **I - Instruction（指令）**：核心任务是什么，具体要做什么动作。
4. **S - Specification（规范/限制）**：字数、语气、禁忌事项、边界条件。
5. **P - Output（输出格式）**：要求它输出什么格式（表格、JSON、Markdown、Python 代码等）。
6. (可选) **E - Examples（示例）**：给 1-2 个参考示例，让它照猫画虎。

---


## 二、 正反案例

### 错误示范（模糊指令）

> “帮我写个关于人工智能的总结。”

- 问题：太宽泛。AI 涵盖极广，总结多长？写给谁看？什么语气？模型只能靠猜，大概率会给你一篇又空又长的废话。

### 正确示范（结构化 Prompt）

> **【角色】**你是一位资深的科技专栏作家，擅长把复杂的技术概念写得通俗易懂。
>
> **【背景】**我的受众是完全没有计算机背景的普通白领，他们需要了解 AI 的现状。
>
> **【指令】**请写一篇关于“人工智能近期发展”的总结。
>
> **【限制】**字数控制在 500 字以内；禁止使用“深度学习”、“Transformer”、“神经网络”等专业术语；使用积极、客观的语气；必须分为 3 个要点进行论述。
>
> **【输出格式】**请以 Markdown 列表的形式输出。

- 效果：模型有了明确的边界，输出质量会呈指数级上升。

## 三、实战技巧

1. **用分隔符隔离数据**：如果你的 Prompt 中包含大量需要处理的数据，一定要用 `"""`、`###`、`<tag>` 把指令和资料分开，防止模型把资料当成了指令。
   - 示例：“请总结以下用三引号括起来的文本：`""" [插入长文本] """`”
2. **思维链提示（CoT）**：遇到需要逻辑推理、数学计算或多条件判断的任务，一定要在结尾加上：**“请先逐步分析，然后再给出最终结论。”**
3. **少样本提示（Few-Shot）**：如果你需要特定格式的答案，直接给它 1-2 个例子。
   - 示例：“请按照以下格式提取信息。示例：输入：‘张三，25岁’，输出：`{'name': '张三', 'age': 25}`。现在请处理：……”
4. **明确边界**：为了防止模型胡说八道，必须设定规则：“如果你不知道答案，或者提供的资料里没有相关内容，请直接回答‘根据现有资料无法回答’，禁止编造。”
5. **角色设定的精细度**：写得越具体越好。
   - 一般：“你是一位程序员。”
   - 具体：“你是一位有 10 年经验的前端架构师，极度重视代码性能和可读性。”
6. **迭代式对话**：**一次性写不出完美的 Prompt**。先用通用基础模版跑一次，看它哪里做得不好、有误，然后针对性地在下一轮对话中纠正。

## 四、Prompt进阶

### 提示词分为两层

1. **System Prompt（系统提示词）**：在对话开始时设置全局指令，定义了 AI 的角色、规则、边界设定、输出格式等。

   - 开发者调用 API（代码层级）
     如果你是通过代码（Python、Node.js 等）调用大模型接口，系统提示词通常作为请求体（Payload）中的独立字段传入。

     - OpenAI (ChatGPT) / 兼容接口：放在 `messages` 数组的第一个元素中，`role` 设为 `"system"`。

       ```json
       {
         "model": "gpt-4o",
         "messages": [
           {"role": "system", "content": "你是一个只讲冷笑话的助手。"},
           {"role": "user", "content": "今天天气怎么样？"}
         ]
       }
       ```

     - Anthropic (Claude)：有专门的 `system` 顶层参数。

       ```json
       {
         "model": "claude-3-opus-20240229",
         "system": "你是一个严谨的数学家。",
         "messages": [{"role": "user", "content": "1+1等于几？"}]
       }
       ```

   - 智能体开发平台（如 Coze 扣子、Dify、字节星火、百度千帆等）
     在这些可视化平台中，系统提示词通常写在“人设与回复逻辑”或“角色设定”的文本框里。

     - 位置：创建 Bot/Agent 的配置页面，通常是最大的那个输入框。
     - 作用：定义 AI 的身份、核心任务、回复风格以及必须遵守的底线规则（即前面提到的“指令隔离”）。

   - 网页版对话框（如 ChatGPT、Kimi、豆包网页端）

     - 普通用户：无法直接设置全局系统提示词。你输入在聊天框里的每一句话，本质上都是 User Prompt（用户提示词）。不过，你可以通过在一段对话的开头发送一段长文本（如：“从现在起，请你扮演一个xxx，遵循以下规则……”）来模拟系统提示词的效果。
     - 自定义 GPTs / 智能体商店：在创建自定义 AI 时，会有一个专门的“Instructions（指令）”输入框，那里就是写系统提示词的地方。

   - 终端命令行工具（如 Cursor、GitHub Copilot、各类 CLI 工具）

     - 配置文件：通常写在项目的特殊配置文件中。例如，使用 Cursor 或类似工具时，可以在项目根目录创建一个 `.cursorrules` 或 `system.md` 文件，里面写入的规则会被作为底层系统提示词注入。
     - 终端配置：某些命令行 AI 工具允许你在环境变量或配置文件中定义默认的系统级指令。

2. **User Prompt（用户提示词）**：用户实际输入的问题。系统提示词的优先级永远高于用户提示词。

### ReAct框架

ReAct = Reasoning + Acting，整体流程为：思考->行动->观察->进入循环。

适用场景：

- 查询外部信息，联网搜索。

- 多步骤任务。

- 需要验证的任务。

- 工具调用。

### Prompt调试方法

Prompt 不是一次就能写好的，也需要迭代优化。好的调试方法是：控制变量，一次只改一个地方。

测试流程：

1. 准备测试用例集——5-10 个有代表性的输入。

2. 写第一个版本的 Prompt——能跑就行，不追求完美。

3. 用所有测试用例测试——记录每个结果。

4. 分析失败案例——找出共性问题。

5. 修改 Prompt——一次只改一处。

6. 重新测试——确认修改有效，没有引入新问题。

7. 重复 4-6——直到满意为止。

### 提示词安全

提示词注入是一种攻击方式，涉及到网络安全方面的知识。

| 安全防护机制 | 核心目的 | 具体实现方式 |
| :--- | :--- | :--- |
| **1. 过滤词（敏感词）** | 拦截明显违规、涉黄、涉政或暴力的输入/输出内容。 | 建立本地敏感词库，使用正则匹配或关键词替换；或在调用 API 前接入云端内容安全审核接口。 |
| **2. 指令隔离** | 防止“提示词注入攻击”（Prompt Injection），确保模型底线不被突破。 | 在代码层面强制分离 `System Prompt`（系统设定）与 `User Prompt`（用户输入） |
| **3. 输出校验** | 确保 AI 返回的内容符合预期的格式和业务逻辑，防止脏数据。 | 使用代码对输出进行解析。防止包含敏感内容。 |
| **4. 双重检查** | 引入独立的“裁判模型”，规避单一模型被绕过的风险。 | 在主模型输出后，将“用户输入 + AI输出”发送给另一个独立的安全审查模型，由该模型判断是否存在越狱、攻击或违规风险。 |
| **5. 限制能力（工具）** | 遵循“最小权限原则”，防止 AI 误调用危险工具导致系统级灾难。 | 在Agent配置中，严格限制可调用的工具列表。 |

---


## **总结**：

你要假设对方是个没有任何背景知识的执行机器，把“你是谁、做什么、怎么做、不要做什么、输出成什么样”交代完整，就能得到想要的结果。
